# 预秒杀可行性分析

## 业务背景

Amazon 秒杀（Lightning Deal / Best Deal）是提升销量和排名的重要手段，但选错ASIN会导致两种损失：
1. **库存不足时做秒杀** → 秒杀中途断货，排名反而下跌，还影响秒杀资格。
2. **淡季做季节品秒杀** → 转化率极低，浪费秒杀名额和广告预算。

本 skill 通过领星ERP真实数据 + SIF市场趋势 + Sorftime产品详情三源交叉验证，给出9维度评分和排名推荐，把"凭感觉选"变成"凭数据选"。

## 当前工作流（人工版）

- 卖家提供一批父ASIN，分析师分别打开领星ERP、SIF、Sorftime查看数据。
- 手动记录每个ASIN的月销量、FBA库存、BSR、流量趋势、评论数、价格、季节性。
- 凭经验判断哪个适合秒杀，耗时2-4小时，容易遗漏库存门槛和季节性窗口。
- 领星ERP Key过期时数据会静默失真（实测差异可达3-30倍），人工很难发现。

## Skill 工作流（自动版）

### 第1步：数据源连接与新鲜度校验

**领星ERP MCP（核心数据源）**
1. 调用 `mcp_LingXing-MCP` 的 `help` 工具，确认返回 `catalogVersion` 字段且 `code:1`。
2. 如果 help 返回失败或 code≠1，标注"领星ERP连接失败"，仅使用 SIF+Sorftime 数据降级分析，在报告中明确标注数据缺失。
3. 连接成功后，用 `search` 工具查找 `query_product_performance_asin_lists`，获取其 `inputSchema`。
4. 用 `action` 工具执行查询，参数映射：
   - `search_field`: `parent_asin`（用户提供父ASIN时）或 `asin`（子ASIN时）
   - `search_value`: 用户提供的ASIN列表
   - `summary_field`: `parent_asin`
   - `start_date` / `end_date`: 当月往前推8个月（覆盖2个季度季节性）
   - `date_view_type`: `month`
   - `date_view_order_type`: `2`（按ASIN分组）
   - `turn_on_summary`: `1`（必填，否则报错）
   - `currency_code`: `USD`
   - `length`: `50`（默认20不够，50覆盖11个ASIN×8月）
   - `sort_field`: `volume`，`sort_type`: `desc`
5. **不限制 `mids` 参数**——限制国家会导致部分ASIN查不到（实测4个ASIN在限定US时返回空）。如需多站点分析，分开查询。
6. 如果返回 `list` 为空，尝试去掉 `mids` 限制重查。

**数据新鲜度校验（关键，踩坑规避）**
- 领星ERP Key过期时，MCP仍会返回数据但内容是缓存/默认值，与真实数据差异可达3-30倍。
- 校验方法：对比同一ASIN在领星和SIF的月销量级，如果差异>3倍，标注"领星数据可能失真，建议重新连接ERP"。
- 报告中必须写明领星MCP的 `catalogVersion`（如 `lingxing-mcp-20260902-v1`）和拉取时间。

### 第2步：库存门槛计算

从领星ERP返回数据中提取每个ASIN的：
- `fba_fulfillable_quantity`（FBA可售）
- `available_inventory.available_inventory`（可用库存，含在途）
- `available_inventory.afn_inbound_receiving_quantity`（入库中）
- `afn_reserved_quantity`（预留）
- `volume`（当月销量）
- `rdate`（数据月份）

**计算公式**：
```
库销比 = FBA可售 ÷ 当月月销量
秒杀需量 = 当月月销量 × 2.5
库存余量 = FBA可售 - 秒杀需量
```

**门槛规则**（秒杀预估增量 = 月销量 × 2.5，覆盖2周秒杀期3-5倍日销 + 2周常规销售）：

| 库销比 | 门槛判定 | 标记 |
|--------|----------|------|
| ≥ 5.0月 | 库存充裕 | ✅ 通过 |
| 2.5-5.0月 | 库存达标 | ✅ 通过 |
| 2.0-2.5月 | 临界 | ⚠ 临界 |
| < 2.0月 | 不足 | ❌ 不通过 |

**未通过门槛的ASIN不参与排名推荐**，但仍在报告中列出并给出补货建议。

### 第3步：SIF市场趋势验证

**ASIN基础属性**
- 调用 `mcp_sif-mcp` 的 `market_get_asin_profile`，传入通过门槛的ASIN列表。
- 提取：价格、评分、评论数、BSR排名、变体数、上架时间、重量尺寸。

**流量趋势**
- 调用 `ops_get_asin_traffic_trend`，获取30天流量变化。
- 提取：流量趋势方向（sharp_growth/mild_growth/stable/mild_decline/sharp_decline）、BSR变化幅度。

**季节性验证**
- 根据ASIN产品类别推断核心关键词（如鞋钉→"track spikes"+"cross country spikes"，圣诞耳环→"christmas earrings"）。
- 调用 `market_get_keyword_root_trend`，获取过去12个月搜索量趋势。
- 判定季节性类型：
  - 旺季爬坡期（搜索量环比上升）：时机分 8-10
  - 旺季峰值期（搜索量达年度高位）：时机分 9-10
  - 淡季低谷期（搜索量环比下降）：时机分 3-5
  - 常青品类（全年波动<30%）：时机分 6-7
- SIF工具返回的 `render_footer` 验证链接必须保留在报告末尾。

### 第4步：Sorftime产品详情（可选补充）

- 调用 `mcp_Sorftime_MCP` 的 `product_detail` 获取FBA费用、佣金、毛利率。
- 如果Sorftime数据不可用，利润维度给5分基准分并标注"利润数据缺失"。

### 第5步：9维度评分

**9维度 × 10分 = 90分制**，完整评分细则见 `references/评分维度细则.md`。

| 维度 | 数据源 | 评分要点 |
|------|--------|----------|
| 销量基础 | 领星ERP | 8月月销量，>1500=9-10, 800-1500=7-8, 300-800=4-6, <300=1-3 |
| 流量趋势 | SIF | 30天流量变化，sharp_growth=10, mild_growth=8, stable=6, decline=3 |
| BSR走势 | SIF | 30天BSR变化，改善>50%=10, 改善20-50%=8, 持平=6, 下滑=3 |
| 价格带 | SIF/Sorftime | $5-8=9-10, $8-10=7-8, $10-15=4-5, >$15=2-3 |
| 评论基础 | SIF | 评论数+星级，>1000条+≥4.5星=10, 500-1000+≥4.3=8 |
| 季节时机 | SIF关键词趋势 | 旺季爬坡=8-10, 常青=6-7, 淡季=3-5 |
| 利润空间 | Sorftime/领星 | 毛利率>40%=10, 30-40%=8, 20-30%=6, <20%=3, 无数据=5 |
| 综合动量 | 综合 | 流量+BSR+销量三者综合趋势 |
| 库存充足度 | 领星ERP | 库销比≥5月=10, 3-5月=7-8, 2.5-3月=6, 2-2.5月=4, 1.5-2月=3, <1.5月=1-2 |

**评分约束**：
- 库存维度 <4分 的ASIN，门槛标记为 ❌，不参与推荐排名。
- 门槛标记为 ⚠ 临界 的ASIN参与排名但标注风险。

### 第6步：生成HTML报告

报告结构（使用ECharts可视化）：

1. **报告头部**：数据源、拉取时间、ERP版本号、评估目标
2. **数据修正提示**（如有）：标注本次数据与上次的差异（针对领星Key过期场景）
3. **Top 3 推荐卡片**：金/银/铜牌，含评分、推荐理由、标签
4. **领星ERP库存+销售总览表**：全部ASIN的8月销量、FBA可售、库销比、门槛判定
5. **季节性分析**：SIF关键词趋势图 + 领星月度销量趋势图
6. **评分矩阵表**：9维度得分明细
7. **Top 3 详细分析**：推荐理由 + 风险提示
8. **未通过门槛ASIN简析**：补货建议
9. **数据可视化**：库存vs销量柱状图、评分vs库销比散点图
10. **方法论说明**：数据来源、评分维度、门槛规则
11. **行动建议**：按优先级排序的执行步骤

**文件命名**：`{N}个ASIN秒杀推荐分析报告.html`，保存到用户工作目录。
**完成信号**：报告保存后告知用户文件路径，并口头总结Top 3推荐和关键数据修正。

## 核心原则 / 踩坑规避

### 领星ERP数据新鲜度（最高优先级）
- 领星MCP Key过期时不会报错，而是返回失真数据。实测案例：B095H2TX95的FBA可售从853件（真实）变成24,295件（缓存），差距28倍。
- 每次使用领星数据前，必须记录 `catalogVersion`。如果用户说"数据不对"或"上次数据和这次差很多"，优先检查Key是否过期。
- 对比方法：领星月销量 vs SIF的 `bought_in_past_month`，差异>3倍则标注失真。

### 不限制国家查询
- 领星查询时设置 `mids:"1"`（仅US站）会导致部分ASIN返回空结果。
- 默认不限制 `mids`，让ERP返回所有站点的数据。如果用户明确只需要US站，再限制。

### 库存门槛是硬约束
- 库销比<2.5月的ASIN**不可秒杀**，不管其他维度多优秀。
- 库销比2.0-2.5月的ASIN可秒杀但标注"临界风险"，秒杀后需立即补货。
- 库销比≥5月的ASIN如果销量低，说明库存积压，秒杀有去库存的战略意义。

### 季节性影响转化率
- 旺季爬坡期做秒杀：搜索量上升+秒杀折扣 = 转化率倍增。
- 淡季做秒杀：搜索量低谷，秒杀折扣也拉不动转化率。
- 常青品类：季节性影响小，看流量和BSR趋势决定时机。

### SIF数据约束
- SIF周数据以周日为每周第一天。
- 当周数据可能因T+1延迟不可用。
- 使用SIF工具后，报告末尾必须保留 `render_footer` 验证链接。

## 触发场景

**会触发**：
- "分析这几个ASIN哪个适合做秒杀"
- "预秒杀分析"
- "秒杀推荐分析"
- "这几个产品能不能做秒杀"
- "帮我看看这批ASIN哪些适合做接下来的秒杀"
- "flash sale analysis"

**不会触发**：
- "秒杀效果怎么样"（秒杀后复盘，不是预分析）
- "补货建议"（库存补货决策，不是秒杀评估）
- "广告怎么投"（广告策略，不是秒杀选择）
- 单个ASIN深度分析（本skill面向批量对比）
